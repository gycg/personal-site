# A股科技研究系列维护记录

这份文档记录“A股科技与未来产业研究路线”从单篇文章扩展为项目化系列后的设计判断、维护规则和后续演进方向。它不是发布清单，而是这个系列的工作手册。

核心目标是让这个系列长期可执行：

```text
研究计划 -> 每周清单 -> 原始资料 -> 研究过程 -> 公开文章 -> 项目页汇总 -> 月度复盘
```

如果后续内容只增加文章数量，却没有形成这条闭环，系列会很快变成散落的股票笔记。当前优化的重点，就是把“写了几篇文章”升级为“建立一套可持续运行的研究系统”。

## 当前结构

- 项目页：`src/pages/projects/a-share-tech-research-roadmap.astro`
- 项目数据：`src/data/a-share-tech-research-plan.ts`
- 系列文章：
  - `src/content/posts/why-stock-research-matters.md`
  - `src/content/posts/annual-report-reading-week-one-kingsoft-byd.md`
  - `src/content/posts/kingsoft-office-week-two-research.md`
  - `src/content/posts/byd-week-three-research.md`
  - `src/content/posts/software-vs-manufacturing-financial-structure.md`

项目页承担“路线图 + 执行看板”的作用，文章承担“每周研究记录 + 阶段性结论”的作用。文章开头链接回项目页，项目页从清单链接到对应文章。

这个结构的关键不是链接本身，而是责任划分：

- 项目页回答：这个系列要研究什么、按什么节奏推进、现在完成到哪里。
- 数据文件回答：每个月、每周、每家公司应该交付什么。
- 文章回答：某一次研究到底读了什么资料、看到了什么证据、形成了什么暂时结论。
- 文档回答：后续维护时应该遵守什么边界，避免把研究写成情绪化观点。

## 本轮优化的核心问题

原始内容已经有完整的一年路线，也已经完成第一个月四篇文章。但如果不做结构优化，会出现三个问题。

第一，计划和执行容易脱节。

长计划写在文章里时，读者很难知道哪些已经完成、哪些只是规划。作者自己后续维护时，也容易忘记某篇文章对应哪个周清单。项目页的作用就是把计划、状态和执行记录放在同一个地方。

第二，文章越多，链接越容易失控。

如果每次都在页面里手写执行记录，新增文章时必须同时改多个地方：文章本身、项目页链接、清单状态、摘要描述。只要漏掉一个，页面就会出现“文章已经发布，但项目页仍显示未完成”的问题。

第三，股票研究文章对资料口径很敏感。

同样叫“年报”，年度报告全文、年度报告摘要、审计报告、业绩快报、季度报告的用途不同。如果不在系列维护文档里明确资料优先级，后续文章很容易把摘要当全文用，或者把审计报告误写成年报全文。

## 本轮优化点

### 1. 从单篇文章升级为项目入口

年度研究路线不再只是文章里的长计划，而是拆成独立项目页。

这样做的价值有三点：

- 降低读者进入成本。新读者不用从某篇周记倒推整个计划，可以直接从项目页看到年度目标、公司分层、七步法、12 个月路线和执行记录。
- 提高后续维护稳定性。项目页是固定入口，文章只是阶段记录。后续第 2 个月、第 3 个月继续新增内容时，不需要反复解释整个背景。
- 让研究计划接受公开复盘。项目页展示完成状态，相当于把“我打算研究什么”和“我实际完成了什么”放在一起，减少只写观点、不交付成果的问题。

判断标准：

- 项目页必须能让不了解这个系列的人在 3 分钟内明白研究目标。
- 项目页不能只展示宏大计划，必须展示真实执行记录。
- 每篇执行文章都应能从项目页找到入口。

### 2. 把月度执行数据化

`monthlyExecutions` 现在按月份保存执行状态。每个月包含月度目标、状态、摘要和 4 周清单；每周清单继续保存标题、目标、清单、交付物、状态、文章链接、文章标题和摘要。

项目页的“月度执行看板”和“执行记录”都从这份数据生成。

这不是为了抽象而抽象，而是为了消除两类维护风险：

- 重复维护风险：同一篇文章标题和摘要如果同时写在项目页和数据文件里，后续改标题时很容易只改一处。
- 状态漂移风险：文章发布后，如果忘记更新项目页，读者看到的进度就是错的。

当前使用的结构是：

```ts
type MonthlyExecution = {
  month: number;
  title: string;
  objective: string;
  status: '已完成' | '进行中' | '未开始';
  summary: string;
  weeklyChecklists: WeeklyChecklist[];
};
```

后续新增第 3 个月、第 4 个月时，不要再新增平铺变量，直接向 `monthlyExecutions` 追加月份。

### 3. 增加月度完成状态摘要

项目页为每个月展示清单进度、文章记录和月度闭环三个状态卡片。

这个模块不是装饰，它解决的是“完成度不可见”的问题。研究系列最容易出现的失败模式是：计划很完整，但执行进度只能从散落文章里猜。状态摘要把完成情况直接暴露出来。

当前三个指标分别对应：

- 清单进度：四周任务是否真的完成。
- 文章记录：研究过程是否已经公开沉淀。
- 月度闭环：是否覆盖公司卡片、财务表、商业模式图、对比文章和复盘。

后续每个月都应该有类似状态，但指标不必完全相同。比如半导体月可以增加“产业链图完成度”，估值月可以增加“三情景模型完成度”，机器人月可以增加“商业化证据清单完成度”。

### 4. 修复正文表格显示问题

正文 `.prose` 现在负责横向滚动，表格宽度使用完整正文宽度，不再限制到 `66ch`。小屏下保留横向滚动，只适度收紧单元格 padding 和字号。

这个问题表面上是 UI 问题，实际会影响研究内容表达。股票研究文章大量使用对比表：收入结构、财务指标、任务清单、资料来源、反方证据。表格如果右侧留白或被压缩，读者会以为数据缺失，甚至误读字段关系。

当前原则：

- 宽表不强行压缩，允许横向滚动。
- 正文段落保持可读宽度，表格可以使用完整正文宽度。
- 手机端优先保留数据结构完整性，不为了适配屏幕牺牲表格含义。

后续如果出现超过 6 列的复杂表格，优先拆表，而不是继续加宽。

### 5. 明确资料口径

股票研究文章优先使用公司定期报告、交易所公告、公司官网投资者关系页面等原始资料。年报摘要只能用于快速提取主要财务数据，不能替代年度报告全文。

这个规则来自前面金山办公资料核对时暴露的问题：同一家公司在不同入口可能出现年度报告全文、摘要、审计报告、公告列表等不同文件。它们都是真实文件，但研究用途不一样。

资料优先级建议如下：

| 资料类型 | 适合用途 | 不适合用途 |
| --- | --- | --- |
| 年度报告全文 | 业务结构、管理层讨论、风险因素、财务附注、研发投入、应收账款、存货 | 快速浏览全部公司 |
| 年度报告摘要 | 提取主要会计数据、利润分配、关键财务指标 | 替代全文做深度研究 |
| 审计报告 | 验证财务报表和审计意见 | 理解完整业务变化 |
| 季度报告 | 跟踪短期经营变化 | 推导长期护城河 |
| 业绩说明会/投资者问答 | 补充管理层解释和市场关注点 | 当作已经验证的事实 |
| 公司官网产品页 | 理解产品形态和客户场景 | 替代收入和利润数据 |

文章中如果使用摘要、审计报告或第三方资料，必须说明用途和局限。

### 6. 建立系列写作闭环

当前固定链条是：

```text
项目计划
  -> 每周清单
  -> 资料来源
  -> 公司卡片 / 财务表 / 商业模式图
  -> 文章记录
  -> 项目页回链
  -> 月度复盘
```

这条链条的意义是强迫每篇文章回答两个问题：

- 这篇文章服务于哪个研究任务？
- 这篇文章新增了什么可复盘的证据或判断？

如果一篇文章不能回答这两个问题，它就不应该放进这个系列。可以作为普通随笔发布，但不应该进入项目执行记录。

## 股票研究文章的深度标准

后续文章不要只停留在“公司做什么、收入多少、股价怎么看”。至少要覆盖四层。

第一层：事实层。

- 公司卖什么产品？
- 客户是谁？
- 收入来自哪些业务？
- 最近三年收入、利润、现金流、研发投入如何变化？

第二层：机制层。

- 为什么客户愿意付钱？
- 公司增加一元收入需要增加什么成本？
- 谁掌握定价权？
- 利润最终留在哪个环节？

第三层：证据层。

- 哪些数据支持当前判断？
- 哪些数据削弱当前判断？
- 哪些指标还没有披露，导致结论只能暂定？

第四层：失效层。

- 如果什么事情发生，原判断需要重写？
- 哪个财务指标恶化后必须重新评估？
- 哪项技术、客户、政策或竞争变化会改变商业逻辑？

只有写到第四层，文章才真正接近研究，而不是公司介绍。

## 后续新增每周记录的步骤

1. 在 `src/data/a-share-tech-research-plan.ts` 的 `monthlyExecutions` 中增加或更新对应月、对应周清单。
2. 如果已经发布文章，填写 `articleHref`、`articleTitle` 和 `articleSummary`。
3. 在 `src/content/posts/` 新增文章，frontmatter 至少包含：
   - `title`
   - `description`
   - `pubDate`
   - `tags`
   - `series`
   - `seriesOrder`
   - `draft: false`
4. 文章第一段说明它属于 `A股科技与未来产业研究路线`，并链接到 `/projects/a-share-tech-research-roadmap/`。
5. 文章正文必须列出资料来源，并区分年度报告全文、摘要、公告、官网和第三方资料。
6. 文章末尾保留风险提示，投资研究内容不构成投资建议。
7. 运行 `npm run check:content`。
8. 运行 `npm run build`。

## 表格写作规则

- 表格适合放“对比”和“验收”，不适合承载过长段落。
- 列数超过 5 列时，优先考虑拆成两张表。
- 数字列右对齐，单位写在表头或单元格里，避免读者猜单位。
- 如果表格来自年报摘要或估算，应在表格前后说明来源和口径。
- 表格不要替代结论。表格后面必须写出观察结果。
- 资料来源表不要只列链接，要写清每份资料在文章中承担什么作用。

## 第一个月已形成的内容链条

- 第 1 周：建立系统、找资料、完成金山办公和比亚迪基础卡片。
- 第 2 周：拆解金山办公的软件收入结构、现金流、研发投入和 AI 商业化证据。
- 第 3 周：拆解比亚迪的销量、收入、利润、资本开支、存货和垂直整合。
- 第 4 周：横向比较软件公司与制造业公司的财务结构差异。

第一个月的核心结论是：研究科技公司不能只看“技术先进”或“行业空间”，还要看收入如何形成、现金流是否真实、资本开支是否沉重、利润最终留在哪个环节。

更具体地说，金山办公和比亚迪的对比提供了一个基础框架：

- 软件公司更适合观察用户留存、订阅转化、毛利率、研发效率和现金流质量。
- 制造业公司更适合观察销量、产能、资本开支、存货、供应链效率和单位经济性。
- 两类公司都不能只看利润表。软件公司要防止把产品叙事直接等同于商业化，制造业公司要防止把销量增长直接等同于股东回报。

## 第二个月已形成的内容链条

- 第 1 周：回到金山办公，拆解个人订阅、WPS 365、WPS AI 和组织客户迁移成本。
- 第 2 周：研究浪潮信息，理解服务器硬件公司的收入弹性、低利润率、库存和回款约束。
- 第 3 周：研究中芯国际，理解晶圆制造的资本开支、折旧、产能利用率和客户验证。
- 第 4 周：横向比较订阅软件、服务器硬件和晶圆制造三类商业模式。

第二个月的核心结论是：商业模式不能只按“轻资产”或“高科技”粗略分类。更有效的问题是：

```text
每增加一元收入，公司需要增加什么成本、什么资产、什么风险？
```

这一轮形成了三类公司对比框架：

- 软件订阅：重点看续费、付费转化、组织扩容、AI收入与AI成本是否匹配。
- 服务器硬件：重点看毛利率、存货、应收账款、客户议价和经营现金流。
- 晶圆制造：重点看资本开支、折旧、产能利用率、良率、客户验证和周期位置。

第 2 个月的四篇文章已经对应到 `monthlyExecutions` 的第 2 个月周清单，专题页通过 `seriesOrder` 继续按顺序聚合。当前“A股科技与未来产业研究路线”系列顺序为：

1. 为什么要进行股票研究？
2. 第 1 个月第 1 周：建立系统与年报阅读入口。
3. 第 1 个月第 2 周：金山办公研究。
4. 第 1 个月第 3 周：比亚迪研究。
5. 第 1 个月第 4 周：软件与制造业财务结构比较。
6. 第 2 个月第 1 周：金山办公软件订阅模式。
7. 第 2 个月第 2 周：浪潮信息服务器硬件模式。
8. 第 2 个月第 3 周：中芯国际晶圆制造模式。
9. 第 2 个月第 4 周：三类商业模式横向比较。

后续进入第 3 个月半导体产业链时，不要重复写“中芯国际是什么公司”这种基础介绍，而要沿着第 2 个月的问题继续深入：产能、折旧、设备、材料、客户验证和产业链利润分布。

## 后续改进方向

### 1. 持续维护月度执行结构

月度执行已经抽象为 `monthlyExecutions`。后续优化重点不是继续加特殊页面逻辑，而是保证每个月的清单、文章链接和状态都回填到同一份数据里。

### 2. 维护专题阅读路径

研究文章已经增加 `series` 和 `seriesOrder`，专题页会自动聚合“A股科技与未来产业研究路线”系列。项目页负责执行看板，专题页负责顺序阅读。

两者定位不同：

- 项目页：偏执行，展示计划、状态、交付物。
- 专题页：偏阅读，展示文章顺序、摘要和完成进度。

### 3. 增加统一公司卡片模板

当前每篇文章手写公司卡片，后续可以沉淀模板：

```text
公司名称：
股票代码：
核心产品：
客户类型：
收入来源：
主要成本：
关键增长点：
最重要风险：
下一步验证问题：
```

这样可以保证不同公司的研究粒度一致，方便横向比较。

### 4. 增加反方证据模板

后续每篇公司研究至少保留一个“反方证据”小节，避免文章只筛选支持原观点的信息。

最低要求：

- 三条支持当前判断的证据；
- 两条削弱当前判断的证据；
- 三个可观察的逻辑失效条件。

### 5. 按月份分组展示执行记录

等第 2 个月完成后，项目页的“执行记录”应改成按月份分组展示。否则 12 个月后会有 24 篇以上文章，单列记录会变得过长。

## 维护底线

- 不把股价短期涨跌写成研究成果。
- 不把行业空间直接写成公司利润。
- 不把年报摘要当作年报全文。
- 不把管理层表述直接当作已经验证的事实。
- 不为了追热点临时打乱月度研究主题。
- 不发布只有资料堆砌、没有判断和反方证据的执行文章。
